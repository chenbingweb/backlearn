## 1. 为什么需要生命周期

### 问题场景

```rust
fn main() {
    let r;
    {
        let x = 5;
        r = &x;     // r 引用 x
    }               // x 在这里被释放
    println!("r: {}", r);  // ❌ r 引用了无效内存！
}
```

编译器错误：
```
error[E0597]: `x` does not live long enough
```

Rust 编译器通过**生命周期**检查引用是否始终有效。

### 生命周期的本质

生命周期不是运行时概念，而是**编译时的静态分析**：
- 标注引用之间的存活关系
- 确保没有悬垂引用
- 零运行时开销

```
变量的生命周期：

let r;           // r 的生命周期: 'a ────────────────
{
    let x = 5;   // x 的生命周期: 'b ───────
    r = &x;      // 要求 'b 包含 'a，但 'b 更短！
}                // x 被释放 ──────
println!("{}", r); // r 无效 ────────────
```

## 2. 生命周期注解语法

### 基本语法

```rust
&i32        // 引用
&'a i32     // 带有显式生命周期的引用
&'a mut i32 // 带有显式生命周期的可变引用
```

`'a` 读作 "lifetime a"，是一个**泛型参数**，表示引用的有效范围。

### 函数中的生命周期

```rust
// 两个字符串切片，返回其中一个
// 'a 表示：返回的引用和参数引用必须具有相同的生命周期
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

fn main() {
    let string1 = String::from("abcd");
    let string2 = "xyz";

    let result = longest(string1.as_str(), string2);
    println!("最长字符串: {}", result);
}
```

含义：
- `'a` 是生命周期参数
- `x: &'a str` — x 的生命周期至少为 `'a`
- `y: &'a str` — y 的生命周期至少为 `'a`
- `-> &'a str` — 返回值的生命周期为 `'a`

**约束**：返回值的生命周期等于两个参数中**较短**的那个。

### 验证生命周期检查

```rust
fn main() {
    let string1 = String::from("long string is long");
    {
        let string2 = String::from("xyz");
        let result = longest(string1.as_str(), string2.as_str());
        println!("最长字符串: {}", result);  // ✅
    }
}
```

```rust
fn main() {
    let string1 = String::from("long string is long");
    let result;
    {
        let string2 = String::from("xyz");
        result = longest(string1.as_str(), string2.as_str());
    }                                           // string2 被释放
    println!("最长字符串: {}", result);  // ❌ result 引用 string2！
}
```

## 3. 生命周期省略规则（Elision）

### 编译器自动推断

有些情况下，编译器可以自动推断生命周期，无需显式标注：

```rust
fn first_word(s: &str) -> &str {   // 等价于 fn first_word<'a>(s: &'a str) -> &'a str
    &s[0..1]
}
```

### 三条省略规则

**规则1**：每个引用参数都有自己的生命周期参数

```rust
fn foo(x: &i32)           // 等价于 fn foo<'a>(x: &'a i32)
fn foo(x: &i32, y: &i32)  // 等价于 fn foo<'a, 'b>(x: &'a i32, y: &'b i32)
```

**规则2**：如果只有一个输入生命周期参数，它会被赋给所有输出生命周期参数

```rust
fn foo(x: &i32) -> &i32   // 等价于 fn foo<'a>(x: &'a i32) -> &'a i32
```

**规则3**：如果有多个输入生命周期参数，但其中一个 `&self` 或 `&mut self`，则 `self` 的生命周期赋给所有输出

```rust
impl MyStruct {
    fn method(&self, x: &str) -> &str  // self 的生命周期赋给返回值
}
```

### 无法省略的情况

```rust
// ❌ 编译器无法推断返回值的生命周期和哪个参数关联
fn longest(x: &str, y: &str) -> &str {
    // ...
}

// ✅ 必须显式标注
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    // ...
}
```

## 4. 方法中的生命周期

```rust
struct ImportantExcerpt<'a> {
    part: &'a str,  // 结构体持有引用，需要生命周期参数
}

impl<'a> ImportantExcerpt<'a> {
    // 规则3：&self 的生命周期自动赋给返回值
    fn level(&self) -> i32 {
        3
    }

    // 需要显式标注：返回值的 lifetime 与参数无关
    fn announce_and_return_part(&self, announcement: &str) -> &str {
        println!("注意！ {}", announcement);
        self.part
    }
}
```

## 5. 'static 生命周期

### 定义

`'static` 表示整个程序的运行期间都有效：

```rust
let s: &'static str = "我有 'static 生命周期";
```

字符串字面量是 `'static` 的，因为它们存储在二进制文件中。

### 误用 'static

```rust
// ❌ 常见误解：认为所有引用都可以标记为 'static
fn bad() -> &'static str {
    let s = String::from("hello");
    &s  // ❌ s 在函数结束时被释放
}
```

### 正确使用

```rust
// ✅ 返回字符串字面量（本身就是 'static）
fn greeting() -> &'static str {
    "Hello, world!"
}

// ✅ 返回编译期常量
const MESSAGE: &'static str = "常量消息";

// ✅ 使用 Box::leak 创建运行时 'static 引用
fn make_static() -> &'static str {
    let s = Box::new(String::from("泄漏的字符串"));
    Box::leak(s).as_str()  // 内存不再被释放！
}
```

⚠️ `Box::leak` 创建的 `'static` 引用不会自动释放，谨慎使用。

## 6. 生命周期与泛型结合

```rust
// 泛型函数 + 生命周期
fn longest_with_an_announcement<'a, T>(
    x: &'a str,
    y: &'a str,
    ann: T,
) -> &'a str
where
    T: std::fmt::Display,
{
    println!("公告！ {}", ann);
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

## 实战练习

### 练习 1：实现字符串分割

```rust
fn split_at_delimiter<'a>(s: &'a str, delimiter: char) -> (&'a str, &'a str) {
    match s.find(delimiter) {
        Some(index) => (&s[..index], &s[index + 1..]),
        None => (s, ""),
    }
}

fn main() {
    let s = "hello=world";
    let (key, value) = split_at_delimiter(s, '=');
    println!("key: {}, value: {}", key, value);
}
```

### 练习 2：返回最长单词

```rust
fn longest_word<'a>(text: &'a str) -> &'a str {
    let mut longest = "";
    for word in text.split_whitespace() {
        if word.len() > longest.len() {
            longest = word;
        }
    }
    longest
}

fn main() {
    let text = "The quick brown fox jumps over the lazy dog";
    println!("最长单词: {}", longest_word(text));
}
```

### 练习 3：生命周期判断

判断以下代码是否能编译：

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = String::from("world");
    let result = longest(s1.as_str(), s2.as_str());
    println!("{}", result);
}

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

答案：✅ 可以编译，因为 s1 和 s2 生命周期相同。

```rust
fn main() {
    let s1 = String::from("hello");
    let result;
    {
        let s2 = String::from("world");
        result = longest(s1.as_str(), s2.as_str());
    }
    println!("{}", result);
}
```

答案：❌ 不能编译，因为 result 的生命周期与 s2 绑定，但 s2 被释放了。

## 今日总结

- [ ] 生命周期是编译时的静态分析，零运行时开销
- [ ] `'a` 是生命周期参数，表示引用的有效范围
- [ ] 函数返回引用时，必须标注生命周期
- [ ] 返回值的生命周期不能超过输入参数的生命周期
- [ ] 三条省略规则让常见模式无需显式标注
- [ ] `'static` 表示整个程序运行期间有效
- [ ] 字符串字面量默认是 `'static`
- [ ] 生命周期可以和泛型参数一起使用
