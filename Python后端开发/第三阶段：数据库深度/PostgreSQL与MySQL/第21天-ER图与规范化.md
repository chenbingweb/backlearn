```
│    password  │         │    status     │
└──────────────┘         └──────────────┘

                         │ OrderItems   │
                         ├──────────────┤
                         │ PK id        │

```

### 关系基数

```
1:1  一对一
┌────┐         ┌────┐
│ A  │─────────│ B  │
└────┘         └────┘
用户表 ───< 身份证表

1:N  一对多
┌────┐ 1       N ┌────┐
│ A  │──────────<│ B  │
└────┘           └────┘
部门表 ───< 员工表

N:M  多对多
┌────┐ N       M ┌────┐
│ A  │──────────<│ B  │
└────┘           └────┘
学生表 ───< 选课表 >─ 课程表
```

## 2. 规范化理论

### 为什么要规范化

```
未规范化问题：
┌────────────────────────────────────┐
│ OrderItem                          │
├────────────────────────────────────┤
│ order_id, order_no, customer_name, │
│ product_names, product_prices...   │
└────────────────────────────────────┘

问题：
1. 数据冗余（product_names 重复）
2. 更新异常（修改商品价格要更新多条）
3. 插入异常（新商品没有订单无法存储）
4. 删除异常（删除订单可能丢失商品信息）
```

### 规范化层次

```
NF0 - 未规范化（存在重复组）
NF1 - 第一范式（原子性）
NF2 - 第二范式（完全函数依赖）
NF3 - 第三范式（传递依赖）
BCNF - Boyce-Codd 范式
NF4 - 第四范式（多值依赖）
NF5 - 第五范式（连接依赖）
```

## 3. 第一范式 (1NF)

### 要求

```
每个字段都是原子的、不可再分的
```

### 示例

```sql
-- 违反 1NF：地址字段不原子
CREATE TABLE customers (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50),
    address VARCHAR(200)  -- "省-市-区-详细地址"
);

-- 符合 1NF：地址拆分为原子字段
CREATE TABLE customers (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50),
    province VARCHAR(50),
    city VARCHAR(50),
    district VARCHAR(50),
    detail_address VARCHAR(100)
);
```

```sql
-- 违反 1NF：多值字段
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    product_ids VARCHAR(100)  -- "1,2,3,4"
);

-- 符合 1NF：使用单独表
CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    order_id INTEGER REFERENCES orders(id),
    product_id INTEGER REFERENCES products(id)
);
```

## 4. 第二范式 (2NF)

### 要求

```
满足 1NF + 非主键字段完全依赖于主键（不存在部分依赖）
```

### 示例

```sql
-- 违反 2NF：复合主键，存在部分依赖
CREATE TABLE order_items (
    order_id INTEGER,      -- 复合主键
    product_id INTEGER,    -- 复合主键
    order_no VARCHAR(50),  -- 依赖于 order_id（部分依赖）
    product_name VARCHAR(100), -- 依赖于 product_id（部分依赖）
    quantity INTEGER,
    price DECIMAL(10,2)
);
-- 问题：order_no 只依赖于 order_id，product_name 只依赖于 product_id

-- 符合 2NF：拆分表
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    order_no VARCHAR(50) NOT NULL,
    user_id INTEGER,
    total_amount DECIMAL(10,2)
);

CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    price DECIMAL(10,2)
);

CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    order_id INTEGER REFERENCES orders(id),
    product_id INTEGER REFERENCES products(id),
    quantity INTEGER,
    price DECIMAL(10,2)
);
```

## 5. 第三范式 (3NF)

### 要求

```
满足 2NF + 非主键字段之间不存在传递依赖
```

### 示例

```sql
-- 违反 3NF：存在传递依赖
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    order_no VARCHAR(50),
    user_id INTEGER,
    user_name VARCHAR(50),      -- 传递依赖：user_name -> user_id -> id
    user_email VARCHAR(100),   -- 传递依赖
    total_amount DECIMAL(10,2)
);
-- user_name 和 user_email 依赖于 user_id，而不是直接依赖于主键 id

-- 符合 3NF：拆分表
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    order_no VARCHAR(50),
    user_id INTEGER REFERENCES users(id),
    total_amount DECIMAL(10,2)
);

CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(100)
);
```

## 6. BCNF 范式

### 要求

```
任何函数依赖的左部必须是候选键
```

### 示例

```sql
-- 违反 BCNF
-- 假设：每个老师只属于一个院系
CREATE TABLE teach (
    id SERIAL PRIMARY KEY,
    teacher_id INTEGER,
    course_id INTEGER,
    department_id INTEGER,  -- 依赖于 teacher_id
    ...
    UNIQUE(teacher_id, department_id)
);
-- teacher_id -> department_id（左部非候选键）

-- 符合 BCNF
CREATE TABLE teachers (
    id SERIAL PRIMARY KEY,
    teacher_id INTEGER UNIQUE,
    department_id INTEGER REFERENCES departments(id)
);

CREATE TABLE teach (
    id SERIAL PRIMARY KEY,
    teacher_id INTEGER REFERENCES teachers(id),
    course_id INTEGER REFERENCES courses(id)
);
```

## 7. 反规范化

### 何时反规范化

```markdown
## 需要反规范化的场景
1. 频繁的 JOIN 查询导致性能问题
2. 读取远多于写入的报表系统
3. 需要冗余数据加速统计查询
4. 历史数据归档（避免多表关联）
```

### 常用反规范化技术

```sql
-- 1. 冗余字段：订单表冗余用户信息
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id),
    user_name VARCHAR(50),        -- 冗余
    user_email VARCHAR(100),     -- 冗余
    shipping_address TEXT,       -- 冗余
    ...
);
-- 优点：查询订单时不需要 JOIN users 表
-- 缺点：更新用户信息时需要同时更新 orders 表

-- 2. 预计算字段：订单表冗余总金额
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    user_id INTEGER,
    total_amount DECIMAL(10,2),     -- 冗余：明细金额之和
    item_count INTEGER,              -- 冗余：明细行数
    ...
);
-- 优点：统计查询更快
-- 缺点：需要触发器或应用层维护一致性

-- 3. 汇总表：日销售汇总
CREATE TABLE daily_sales (
    date DATE PRIMARY KEY,
    order_count INTEGER,
    total_amount DECIMAL(10,2),
    customer_count INTEGER,
    ...
);
-- 定期刷新汇总数据
```

### 维护数据一致性

```sql
-- 使用触发器维护冗余字段
CREATE OR REPLACE FUNCTION sync_order_user_info()
RETURNS TRIGGER AS $$
BEGIN
    UPDATE orders
    SET user_name = u.name,
        user_email = u.email
    FROM users u
    WHERE orders.user_id = u.id
    AND orders.id = NEW.id;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER sync_user_info
    AFTER INSERT ON orders
    FOR EACH ROW
    EXECUTE FUNCTION sync_order_user_info();
```

## 8. 实战练习

### 练习：电商数据库规范化

```sql
-- 原始未规范化设计
CREATE TABLE everything (
    order_id, order_no, order_date,
    customer_id, customer_name, customer_phone, customer_address,
    product_ids, product_names, product_prices, quantities,
    total_amount, discount_amount, payment_amount
);

-- 第一步：满足 1NF（原子化）
-- 拆分 order_items（商品列表）
-- 地址字段原子化

-- 第二步：满足 2NF（消除部分依赖）
-- 订单表：只包含订单本身的信息
-- 订单明细表：通过外键关联商品

-- 第三步：满足 3NF（消除传递依赖）
-- 用户信息独立到 users 表
-- 商品信息独立到 products 表
-- 订单表通过外键引用

-- 最终规范化设计
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50),
    phone VARCHAR(20),
    ...
);

CREATE TABLE addresses (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id),
    receiver_name VARCHAR(50),
    phone VARCHAR(20),
    province VARCHAR(50),
    city VARCHAR(50),
    district VARCHAR(50),
    detail_address VARCHAR(200),
    ...
);

CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(50),
    ...
);

CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    price DECIMAL(10,2),
    category_id INTEGER REFERENCES categories(id),
    ...
);

CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    order_no VARCHAR(50) UNIQUE,
    user_id INTEGER REFERENCES users(id),
    address_id INTEGER REFERENCES addresses(id),
    total_amount DECIMAL(10,2),
    ...
);

CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    order_id INTEGER REFERENCES orders(id),
    product_id INTEGER REFERENCES products(id),
    product_name VARCHAR(100),  -- 冗余：避免 JOIN
    price DECIMAL(10,2),       -- 冗余：记录下单时的价格
    quantity INTEGER,
    subtotal DECIMAL(10,2)
);
```
