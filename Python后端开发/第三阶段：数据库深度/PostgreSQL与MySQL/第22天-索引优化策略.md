## 1. 索引设计流程

### 分析步骤

```
┌─────────────┐
│ 识别慢查询   │  <- EXPLAIN ANALYZE
└──────┬──────┘
       ▼
┌─────────────┐
│ 分析查询模式 │  <- WHERE、ORDER BY、JOIN
└──────┬──────┘
       ▼
┌─────────────┐
│ 选择索引类型 │  <- B-Tree、GIN、HASH
└──────┬──────┘
       ▼
┌─────────────┐
│ 创建并验证   │  <- 监控性能
└─────────────┘
```

### 识别需要索引的查询

```sql
-- 1. 识别高频查询
SELECT
    query,
    calls,
    total_time,
    mean_time,
    rows
FROM pg_stat_statements
ORDER BY calls DESC
LIMIT 20;

-- 2. 识别慢查询
SELECT
    query,
    mean_time,
    rows
FROM pg_stat_statements
WHERE mean_time > 100  -- 超过 100ms
ORDER BY mean_time DESC;

-- 3. 分析特定表访问
SELECT
    schemaname,
    relname,
    seq_scan,
    idx_scan,
    seq_scan * 100 / (seq_scan + idx_scan + 1) AS seq_scan_pct
FROM pg_stat_user_tables
ORDER BY seq_scan DESC;
```

## 2. 索引类型选择

### B-Tree 索引（默认）

```sql
-- 适用场景：
-- 1. 等值查询：WHERE status = 'active'
-- 2. 范围查询：WHERE price > 100
-- 3. 排序：ORDER BY created_at
-- 4. 前缀匹配：WHERE name LIKE 'abc%'

-- 创建
CREATE INDEX idx_orders_status ON orders(status);
CREATE INDEX idx_products_price ON products(price);
CREATE INDEX idx_users_created ON users(created_at DESC);

-- 复合索引
CREATE INDEX idx_orders_user_status ON orders(user_id, status);
-- 适用于：WHERE user_id = 1 AND status = 'pending'
--         WHERE user_id = 1（最左前缀）
```

### Hash 索引

```sql
-- 适用场景：精确等值查询
-- WHERE email = 'test@example.com'

CREATE INDEX idx_users_email_hash ON users USING hash(email);

-- 注意：不支持范围查询、不支持排序
```

### GIN 索引（PostgreSQL）

```sql
-- 适用场景：JSON、数组、全文搜索

-- JSON 索引
CREATE INDEX idx_products_specs ON products USING gin(specs);
-- 查询：WHERE specs @> '{"color": "red"}'

-- 数组索引
CREATE INDEX idx_products_tags ON products USING gin(tags);
-- 查询：WHERE tags && ARRAY['热门', '新品']

-- 全文搜索
CREATE INDEX idx_articles_content ON articles USING gin(to_tsvector('chinese', content));
```

### GiST 索引（PostgreSQL）

```sql
-- 适用场景：地理空间数据、范围查询

-- 地理空间
CREATE INDEX idx_locations_coords ON locations USING gist(coordinates);

-- 范围查询
CREATE INDEX idx_reservations_period ON reservations USING gist(period);
-- WHERE period && '[2024-01-01,2024-01-31]'::daterange
```

## 3. 复合索引设计

### 最左前缀原则

```sql
-- 索引：(a, b, c)
-- 有效查询：
-- WHERE a = 1
-- WHERE a = 1 AND b = 2
-- WHERE a = 1 AND b = 2 AND c = 3

-- 无效查询：
-- WHERE b = 2
-- WHERE c = 3
-- WHERE b = 2 AND c = 3
```

### 列顺序选择

```sql
-- 原则：高选择性列放前面

-- 选择性计算
SELECT
    column_name,
    COUNT(DISTINCT column_name) AS distinct_count,
    ROUND(COUNT(DISTINCT column_name)::NUMERIC / COUNT(*), 4) AS selectivity
FROM table_name
GROUP BY column_name
ORDER BY selectivity DESC;

-- 示例：status 选择性低，created_at 选择性高
-- 错误顺序：
CREATE INDEX idx_orders_status_created ON orders(status, created_at);

-- 正确顺序：
CREATE INDEX idx_orders_created_status ON orders(created_at DESC, status);
```

### 覆盖索引

```sql
-- 包含所有需要查询的列，避免回表
CREATE INDEX idx_orders_cover ON orders(user_id, status)
INCLUDE (total_amount, created_at);
-- 查询可直接从索引返回：
-- SELECT user_id, status, total_amount, created_at
-- FROM orders WHERE user_id = 1 AND status = 'pending'
```

## 4. 索引维护

### 查看索引使用

```sql
-- 查看索引使用统计
SELECT
    indexrelname,
    idx_scan,
    idx_tup_read,
    idx_tup_fetch
FROM pg_stat_user_indexes
WHERE schemaname = 'public'
ORDER BY idx_scan ASC;

-- 查看未使用的索引
SELECT
    schemaname || '.' || relname AS table,
    indexrelname AS index,
    pg_size_pretty(pg_relation_size(i.indexrelid)) AS index_size
FROM pg_stat_user_indexes u
JOIN pg_index i ON u.indexrelid = i.indexrelid
JOIN pg_class c ON i.indrelid = c.oid
WHERE idx_scan = 0
AND NOT EXISTS (
    SELECT 1 FROM pg_constraint WHERE conindid = i.indexrelid
)
ORDER BY pg_relation_size(i.indexrelid) DESC;
```

### 删除无用索引

```sql
-- 删除未使用的索引
DROP INDEX IF EXISTS idx_unused_index;

-- PostgreSQL 自动识别未使用索引
-- 查看建议删除的索引（需要 pg_stat_statements）
SELECT 'DROP INDEX ' || indexrelname || ';' AS drop_statement
FROM pg_stat_statements ps
JOIN pg_stat_user_indexes psui ON ps.queryid = ps.calls
WHERE NOT EXISTS (
    SELECT 1 FROM pg_constraint WHERE conindid = psui.indexrelid
)
AND idx_scan = 0;
```

### 重建索引

```sql
-- 重建索引（PostgreSQL 11+）
REINDEX INDEX CONCURRENTLY idx_orders_status;

-- 重建所有索引
REINDEX TABLE CONCURRENTLY orders;

-- 分析表
ANALYZE orders;

-- 批量重建损坏的索引
SELECT 'REINDEX INDEX CONCURRENTLY ' || indexname || ';' AS cmd
FROM pg_indexes
WHERE tablename = 'orders';
```

## 5. 特殊索引策略

### 部分索引

```sql
-- 只索引活跃数据
CREATE INDEX idx_active_orders ON orders(user_id, created_at)
WHERE status = 'active';

-- 只索引大额订单
CREATE INDEX idx_large_orders ON orders(user_id)
WHERE total_amount > 10000;

-- 查询时自动使用
SELECT * FROM orders
WHERE user_id = 1
AND status = 'active'
AND created_at > '2024-01-01';
```

### 表达式索引

```sql
-- 对函数结果建立索引
CREATE INDEX idx_users_email_lower ON users(LOWER(email));
SELECT * FROM users WHERE LOWER(email) = 'test@example.com';

-- 对计算结果建立索引
CREATE INDEX idx_products_discount ON products(price * (1 - discount));
CREATE INDEX idx_orders_year ON orders(EXTRACT(YEAR FROM created_at));

-- 范围查询优化
CREATE INDEX idx_products_price_range ON products(price)
WHERE price BETWEEN 100 AND 500;
```

### 排序索引

```sql
-- 优化 ORDER BY DESC
CREATE INDEX idx_products_price_desc ON products(price DESC);

-- 优化多列排序
CREATE INDEX idx_orders_status_created ON orders(status, created_at DESC);

-- 查询
SELECT * FROM orders
WHERE status = 'pending'
ORDER BY created_at DESC
LIMIT 10;
```

## 6. MySQL 索引特点

### InnoDB 索引

```sql
-- 主键索引（聚簇索引）
-- 数据按主键顺序存储
-- 每个表只有一个主键索引

-- 辅助索引
-- 非主键列的索引
-- 叶子节点存储主键值

-- 查询优化：尽量使用主键查询
SELECT * FROM orders WHERE id = 1;  -- 直接通过主键访问
SELECT * FROM orders WHERE order_no = 'xxx';  -- 先查辅助索引，再回表

-- 覆盖索引优化
CREATE INDEX idx_order_no_cover ON orders(order_no)
INCLUDE (user_id, status, total_amount);
-- 直接从索引返回，无需回表
```

### 前缀索引

```sql
-- 对长字符串建立前缀索引
ALTER TABLE products ADD INDEX idx_description (description(50));

-- 选择合适的前缀长度
SELECT
    COUNT(DISTINCT LEFT(description, 10)) / COUNT(*) AS selectivity_10,
    COUNT(DISTINCT LEFT(description, 20)) / COUNT(*) AS selectivity_20,
    COUNT(DISTINCT LEFT(description, 30)) / COUNT(*) AS selectivity_30
FROM products;
```

### 联合索引顺序

```sql
-- MySQL 联合索引同样遵循最左前缀原则
-- (a, b, c) 支持 a、ab、abc

-- 优化 IN 查询
CREATE INDEX idx_status_user ON orders(status, user_id);
-- 支持 WHERE status IN ('pending', 'paid') AND user_id = 1
-- 支持 WHERE status = 'pending' AND user_id = 1
```

## 7. 实战练习

### 练习：订单系统索引优化

```sql
-- 原始查询分析
EXPLAIN ANALYZE
SELECT
    o.order_no,
    o.created_at,
    o.total_amount,
    u.username,
    u.email
FROM orders o
JOIN users u ON o.user_id = u.id
WHERE o.status = 'completed'
AND o.created_at > '2024-01-01'
ORDER BY o.created_at DESC
LIMIT 20;

-- 问题：
-- 1. status 过滤后数据量大
-- 2. created_at 排序无合适索引
-- 3. JOIN 导致大量回表

-- 优化方案：

-- 1. 复合索引覆盖
CREATE INDEX idx_orders_cover
ON orders(status, created_at DESC)
INCLUDE (user_id, total_amount);

-- 2. 用户表索引
CREATE INDEX idx_users_username ON users(username);

-- 3. 验证优化
EXPLAIN ANALYZE
SELECT
    o.order_no,
    o.created_at,
    o.total_amount,
    u.username,
    u.email
FROM orders o
JOIN users u ON o.user_id = u.id
WHERE o.status = 'completed'
AND o.created_at > '2024-01-01'
ORDER BY o.created_at DESC
LIMIT 20;
-- 期望：Index Only Scan，使用覆盖索引
```

## 今日总结
