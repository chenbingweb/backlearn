## 1. 事务基础

### 事务概念

事务是数据库操作的逻辑单元，具有 ACID 特性：

```
Atomic（原子性）：事务中的操作要么全部成功，要么全部失败
Consistency（一致性）：事务执行前后，数据库状态保持一致
Isolation（隔离性）：并发事务相互隔离，互不干扰
Durability（持久性）：事务提交后，修改永久保存
```

### 事务语法

```sql
-- PostgreSQL
BEGIN;
-- 或
START TRANSACTION;

-- 执行操作
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

-- 提交
COMMIT;

-- 回滚
ROLLBACK;
```

```sql
-- MySQL
START TRANSACTION;

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

COMMIT;
-- 或
ROLLBACK;
```

### 自动提交

```sql
-- PostgreSQL 默认手动提交
SHOW autocommit;  -- off

-- 设为自动提交
SET autocommit = on;

-- MySQL 默认自动提交
SHOW VARIABLES LIKE 'autocommit';  -- ON

-- 手动开启事务
SET autocommit = OFF;
```

## 2. 事务隔离级别

### 四种隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| READ UNCOMMITTED | 可能 | 可能 | 可能 |
| READ COMMITTED | 不可能 | 可能 | 可能 |
| REPEATABLE READ | 不可能 | 不可能 | 可能* |
| SERIALIZABLE | 不可能 | 不可能 | 不可能 |

### 设置隔离级别

```sql
-- PostgreSQL
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;

-- MySQL
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SET SESSION TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

### 隔离级别示例

```sql
-- 脏读示例
-- 事务 A                   事务 B
-- BEGIN;                   BEGIN;
-- UPDATE SET balance=0;    --
-- -- 未提交                  SELECT balance;  -- 读到 0（脏读）
-- ROLLBACK;                 --
--                           UPDATE SET balance=100;  -- 基于脏数据

-- 不可重复读示例
-- 事务 A                   事务 B
-- BEGIN;                   BEGIN;
-- SELECT balance; -- 100    --
--                           UPDATE SET balance=200;
--                           COMMIT;
-- SELECT balance; -- 200    -- 同一事务内两次读取不同
```

## 3. PostgreSQL MVCC

### MVCC 机制

PostgreSQL 使用 MVCC（多版本并发控制）实现事务隔离：

```sql
-- 事务 ID
SELECT txid_current();  -- 当前事务 ID

-- 元组结构（内部）
-- (xmin, xmax, xmin_cmd, xmax_cmd, ctid)
-- xmin: 插入事务 ID
-- xmax: 删除/更新事务 ID

-- 查看元组信息（PostgreSQL）
SELECT
    xmin,
    xmax,
    ctid,
    name
FROM products;
```

### 可见性判断

```sql
-- 事务快照
SELECT * FROM pg_stat_activity;

-- 查看事务快照状态
SELECT
    datname,
    numbackends,
    xact_commit,
    xact_rollback
FROM pg_stat_database;

-- 长时间运行的事务（阻塞 VACUUM）
SELECT
    pid,
    usename,
    state,
    query,
    query_start
FROM pg_stat_activity
WHERE state != 'idle'
AND query_start < CURRENT_TIMESTAMP - INTERVAL '5 minutes';
```

###  VACUUM 与 MVCC

```sql
-- 手动 VACUUM
VACUUM products;

-- VACUUM 并分析
VACUUM ANALYZE products;

-- 查看死元组
SELECT
    relname,
    n_dead_tup,
    n_live_tup,
    last_vacuum
FROM pg_stat_user_tables
WHERE n_dead_tup > 1000;
```

## 4. 锁机制

### 锁类型

```sql
-- 共享锁 vs 排他锁
-- 共享锁：多个事务可同时持有
-- 排他锁：只能有一个事务持有

-- 表级锁
LOCK TABLE products IN SHARE MODE;      -- 共享
LOCK TABLE products IN SHARE UPDATE MODE;
LOCK TABLE products IN EXCLUSIVE MODE;  -- 排他

-- 行级锁（PostgreSQL）
SELECT * FROM products WHERE id = 1 FOR UPDATE;  -- FOR UPDATE
SELECT * FROM products WHERE id = 1 FOR SHARE;   -- FOR SHARE

-- MySQL 行级锁
SELECT * FROM products WHERE id = 1 FOR UPDATE;  -- 排他锁
SELECT * FROM products WHERE id = 1 LOCK IN SHARE MODE;  -- 共享锁
```

### 死锁处理

```sql
-- 死锁示例
-- 事务 A               事务 B
-- BEGIN;               BEGIN;
-- UPDATE p1 SET...     UPDATE p2 SET...
-- UPDATE p2 SET...     UPDATE p1 SET...
-- -- 阻塞               -- 死锁！

-- PostgreSQL 自动检测死锁并回滚一个事务
-- ERROR: deadlock detected

-- 解决：按固定顺序访问资源
-- 始终先更新 p1，再更新 p2
```

### 查看锁等待

```sql
-- PostgreSQL 查看锁
SELECT
    l.pid,
    l.locktype,
    l.relation::regclass,
    l.mode,
    l.granted,
    a.usename,
    a.query
FROM pg_locks l
JOIN pg_stat_activity a ON l.pid = a.pid
WHERE l.pid != pg_backend_pid();

-- 杀死阻塞进程
SELECT pg_terminate_backend(pid) FROM pg_stat_activity
WHERE pid = 12345;

-- MySQL 查看锁
SHOW ENGINE INNODB STATUS;
SHOW PROCESSLIST;
```

## 5. 事务应用场景

### 转账操作

```python
import psycopg2

def transfer_funds(from_account, to_account, amount):
    conn = psycopg2.connect("dbname=test user=postgres")
    try:
        with conn:
            with conn.cursor() as cur:
                # 扣款
                cur.execute(
                    "UPDATE accounts SET balance = balance - %s WHERE id = %s",
                    (amount, from_account)
                )
                # 收款
                cur.execute(
                    "UPDATE accounts SET balance = balance + %s WHERE id = %s",
                    (amount, to_account)
                )
                # 检查余额（防止透支）
                cur.execute(
                    "SELECT balance FROM accounts WHERE id = %s",
                    (from_account,)
                )
                balance = cur.fetchone()[0]
                if balance < 0:
                    raise Exception("余额不足")
        conn.commit()
    except Exception as e:
        conn.rollback()
        raise e
```

## 6. Savepoint 保存点

```sql
-- 设置保存点
BEGIN;
INSERT INTO users (name) VALUES ('Alice');

SAVEPOINT sp1;
INSERT INTO users (name) VALUES ('Bob');

ROLLBACK TO SAVEPOINT sp1;  -- 回滚到保存点

INSERT INTO users (name) VALUES ('Charlie');

COMMIT;  -- 提交：Alice 和 Charlie
```

```python
# Python 使用保存点
with conn:
    with conn.cursor() as cur:
        cur.execute("INSERT INTO users (name) VALUES ('Alice')")
        cur.execute("SAVEPOINT sp1")
        cur.execute("INSERT INTO users (name) VALUES ('Bob')")
        cur.execute("ROLLBACK TO SAVEPOINT sp1")
        cur.execute("INSERT INTO users (name) VALUES ('Charlie')")
```

## 7. 事务隔离级别选择

```sql
-- READ COMMITTED（默认）
-- 适用：大多数业务场景
-- 优点：性能好，避免脏读
-- 缺点：可能出现不可重复读

-- REPEATABLE READ
-- 适用：金融交易、库存管理
-- 优点：同一事务内多次读取一致
-- 缺点：性能开销较大

-- SERIALIZABLE
-- 适用：高并发写入、避免幻读
-- 优点：最强隔离级别
-- 缺点：性能最差，可能事务失败

-- 建议：
-- 大多数场景：READ COMMITTED
-- 财务相关：REPEATABLE READ
-- 高并发写入：SERIALIZABLE
```
