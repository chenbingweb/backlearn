## 1. 索引基础

### 什么是索引

索引是数据库中一种特殊的数据结构，用于加速数据检索，如同书籍的目录。

```
无索引：全表扫描 -> O(n)
有索引：B+树查找 -> O(log n)
```

### 索引的优缺点

```
✅ 优点：
- 大幅提升查询速度
- 减少数据库 I/O
- 加速排序和分组

❌ 缺点：
- 占用存储空间
- 降低写入性能（INSERT/UPDATE/DELETE）
- 维护索引需要开销
```

## 2. 创建索引

### 基本语法

```sql
-- 创建索引
CREATE INDEX idx_products_category ON products(category);

-- 创建唯一索引
CREATE UNIQUE INDEX idx_users_email ON users(email);

-- 多列索引
CREATE INDEX idx_orders_user_status ON orders(user_id, status);

-- PostgreSQL 指定索引类型
CREATE INDEX idx_products_name ON products USING btree(name);
CREATE INDEX idx_products_name_gin ON products USING gin(name);  -- JSON/数组
CREATE INDEX idx_products_name_hash ON products USING hash(name);
```

### MySQL 索引语法

```sql
-- 创建索引
CREATE INDEX idx_products_category ON products(category);

-- 创建唯一索引
CREATE UNIQUE INDEX idx_users_email ON users(email);

-- 添加索引
ALTER TABLE products ADD INDEX idx_category (category);

-- 全文索引
ALTER TABLE articles ADD FULLTEXT INDEX idx_content (content);
```

### 查看索引

```sql
-- PostgreSQL
\d products              -- 查看表结构
\d+ products            -- 查看表结构和大小的详细信息
SELECT indexname, indexdef FROM pg_indexes WHERE tablename = 'products';

-- MySQL
SHOW INDEX FROM products;
SHOW CREATE TABLE products;
```

## 3. 索引类型

### B-Tree 索引（默认）

```sql
-- B-Tree：平衡多叉树，适合范围查询
-- 适用于：=、<、>、BETWEEN、LIKE 'prefix%'

-- 默认索引类型
CREATE INDEX idx_products_price ON products(price);

-- 复合索引
CREATE INDEX idx_products_cat_price ON products(category, price);

-- 适用场景
-- ✅ WHERE category = 'electronics'
-- ✅ WHERE category = 'electronics' AND price > 500
-- ✅ WHERE category IN ('electronics', 'books')
-- ❌ WHERE price > 500（最左前缀不匹配）
```

### Hash 索引

```sql
-- Hash：哈希表，适合精确匹配
-- 适用于：=、!=

CREATE INDEX idx_users_email_hash ON users USING hash(email);

-- 适用场景
-- ✅ WHERE email = 'alice@example.com'
-- ❌ WHERE email LIKE 'alice%'
-- ❌ WHERE email > 'alice'
```

### GIN 索引（PostgreSQL）

```sql
-- GIN：倒排索引，适合 JSON、数组、全文搜索

-- JSON 索引
CREATE INDEX idx_products_specs_gin ON products USING gin(specs);

-- 数组索引
CREATE INDEX idx_products_tags_gin ON products USING gin(tags);

-- 适用场景
-- ✅ WHERE specs @> '{"color": "red"}'
-- ✅ WHERE tags && ARRAY['热门', '新品']
```

### GiST 索引（PostgreSQL）

```sql
-- GiST：几何索引，适合地理空间数据

-- 地理空间索引
CREATE INDEX idx_locations_geo ON locations USING gist(coordinates);

-- 适用场景
-- ✅ WHERE coordinates && ST_MakeBox2D(point1, point2)
-- ✅ 用于几何图形相交查询
```

### 全文索引

```sql
-- PostgreSQL 全文索引
CREATE INDEX idx_articles_content_fts ON articles USING gin(to_tsvector('chinese', content));

-- 搜索
SELECT * FROM articles
WHERE to_tsvector('chinese', content) @@ to_tsquery('chinese', 'SQL 数据库');

-- MySQL 全文索引
ALTER TABLE articles ADD FULLTEXT INDEX idx_content (title, content);

-- 搜索
SELECT * FROM articles WHERE MATCH(title, content) AGAINST('SQL 数据库');
```

## 4. 复合索引

### 最左前缀原则

```sql
-- 复合索引 (category, status, price)
CREATE INDEX idx_products ON products(category, status, price);

-- ✅ 有效的查询
SELECT * FROM products WHERE category = 'electronics';
SELECT * FROM products WHERE category = 'electronics' AND status = 'active';
SELECT * FROM products WHERE category = 'electronics' AND status = 'active' AND price > 100;

-- ❌ 无效的查询（违反最左前缀）
SELECT * FROM products WHERE status = 'active';
SELECT * FROM products WHERE price > 100;
SELECT * FROM products WHERE status = 'active' AND price > 100;
```

### 索引列顺序

```sql
-- 选择性高的列放前面
CREATE INDEX idx_products ON products(status, category, price);
-- status 基数小，不适合放前面

-- 更好的顺序
CREATE INDEX idx_products ON products(category, status, price);
-- category 选择性高，放前面
```

## 5. 索引管理

### 删除索引

```sql
-- PostgreSQL
DROP INDEX idx_products_category;
DROP INDEX IF EXISTS idx_products_category;

-- MySQL
DROP INDEX idx_products_category ON products;
```

### 重命名索引

```sql
-- PostgreSQL
ALTER INDEX idx_products_category RENAME TO idx_products_cat;

-- MySQL
ALTER TABLE products RENAME INDEX idx_products_category TO idx_products_cat;
```

### 查看索引使用情况

```sql
-- PostgreSQL EXPLAIN
EXPLAIN SELECT * FROM products WHERE category = 'electronics';

-- PostgreSQL 索引建议
SELECT
    schemaname,
    tablename,
    indexname,
    idx_scan,
    idx_tup_read,
    idx_tup_fetch
FROM pg_stat_user_indexes
WHERE tablename = 'products'
ORDER BY idx_scan ASC;

-- MySQL EXPLAIN
EXPLAIN SELECT * FROM products WHERE category = 'electronics';
EXPLAIN ANALYZE SELECT * FROM products WHERE category = 'electronics';
```

## 6. 索引设计原则

### 何时创建索引

```sql
-- ✅ 创建索引
-- 1. 主键自动创建索引
-- 2. 外键列（加速 JOIN）
-- 3. WHERE 频繁使用的列
-- 4. ORDER BY / GROUP BY 列
-- 5. DISTINCT 列

-- ❌ 不创建索引
-- 1. 数据量小的表
-- 2. 频繁更新的列
-- 3. 选择性低的列（如性别、状态）
-- 4. 不出现在 WHERE 的列
```

### 选择性计算

```sql
-- 选择性 = 不同值数量 / 总行数
-- 选择性越高，越适合建索引

SELECT
    category,
    COUNT(*) AS cnt,
    COUNT(DISTINCT category) AS distinct_cnt,
    ROUND(COUNT(DISTINCT category)::DECIMAL / COUNT(*), 4) AS selectivity
FROM products
GROUP BY category;

-- 高选择性（>0.1）适合索引
-- 低选择性（<0.01）不适合索引
```

### 索引设计建议

```sql
-- 1. 主键索引
-- id 通常是自增整数
CREATE TABLE users (
    id SERIAL PRIMARY KEY  -- 自动创建主键索引
);

-- 2. 唯一约束
CREATE UNIQUE INDEX idx_users_email ON users(email);

-- 3. 常见查询索引
-- 场景：按分类和状态查询
CREATE INDEX idx_products_cat_status ON products(category, status);

-- 场景：按日期范围查询
CREATE INDEX idx_orders_created ON orders(created_at DESC);

-- 4. 避免重复索引
-- 已有主键索引，不需在 id 上再建索引
```

## 7. 实战练习

### 练习 1：分析与优化

```sql
-- 分析慢查询
EXPLAIN ANALYZE
SELECT * FROM orders
WHERE status = 'pending'
  AND created_at > CURRENT_TIMESTAMP - INTERVAL '7 days'
ORDER BY created_at DESC;

-- 创建优化索引
CREATE INDEX idx_orders_status_created ON orders(status, created_at DESC);

-- 验证优化效果
EXPLAIN ANALYZE
SELECT * FROM orders
WHERE status = 'pending'
  AND created_at > CURRENT_TIMESTAMP - INTERVAL '7 days'
ORDER BY created_at DESC;
```

### 练习 2：多表查询优化

```sql
-- 查看 JOIN 是否使用索引
EXPLAIN
SELECT u.username, o.order_no, o.total
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.status = 'completed';

-- 确保外键列有索引
CREATE INDEX IF NOT EXISTS idx_orders_user_id ON orders(user_id);
```

## 今日总结

- [ ] 索引加速查询，如同书籍目录
- [ ] `CREATE INDEX` 创建索引，`DROP INDEX` 删除
